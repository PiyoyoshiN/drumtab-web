# 手動テストチェックリスト

DrumTab Web の変更後は、可能な範囲で次の観点を確認します。特に読み込み、表示、再生、MIDI 書き出しの既存フローを壊さないことを重視します。

## ビルド

- [ ] `npm run build` が成功する。
- [ ] `npm run check:samples` が成功する。
- [ ] `npm run check:grid` が成功する。
- [ ] `npm run check` が成功する。

## JSON 読み込み

- [ ] `public/samples/basic-rock-16th.json` を読み込める。
- [ ] ステータスに JSON 読み込み成功とイベント数が表示される。
- [ ] Grid 表示で `Grid 16th | BPM ...` のメタ情報と `Bar` / `Beat` / `Count` のヘッダーが表示される。
- [ ] 小節先頭は `|`、拍先頭は `:` で区別できる。
- [ ] ハイハット、スネア、バスドラが `HH closed` / `SN snare` / `BD kick` の行で追える。
- [ ] 1小節目冒頭のクラッシュ、ハイハット、バスドラが同じ縦位置に揃う。
- [ ] 4小節目終盤のハイハット、スネア、タム、キックの同時または近接イベントが各レーンで読み取れる。
- [ ] Grid 解像度を 8th / 16th / 32nd に切り替えても小節線・拍線・セル幅が破綻しない。
- [ ] Quantize スライダーを動かしてもアプリが例外で止まらない。

## MIDI 読み込み・書き出し

- [ ] MIDI ファイルを読み込める。
- [ ] 読み込み後に Grid または Score 表示へ切り替えられる。
- [ ] Export MIDI ボタンで MIDI ファイルを書き出せる。
- [ ] 書き出した MIDI を再度読み込んでもアプリが止まらない。

## 音声・動画読み込み

- [ ] `.wav` または `.mp3` を読み込んだとき、解析完了または分かりやすい失敗メッセージが表示される。
- [ ] `.mp4` または `.webm` を読み込んだとき、音声抽出から解析まで進む、または分かりやすい失敗メッセージが表示される。
- [ ] 音声解析精度が限定的であることを前提に、表示が空でも UI が壊れない。

## 再生

- [ ] Play ボタンで再生が開始する。
- [ ] Stop ボタンで再生が停止する。
- [ ] 再生中に再生ヘッドまたは状態表示が破綻しない。
- [ ] Speed スライダーを変えてから再生すると速度が変わる。

## Score 表示

- [ ] Score 表示へ切り替えても例外でアプリが止まらない。
- [ ] イベント数が多い入力でも、少なくとも壊れにくい確認表示として動作する。
- [ ] 本格的な五線譜品質を期待せず、Grid 表示の補助として確認する。

## 譜面としての読みやすさ

- [ ] `Bar` 行で小節番号が分かる。
- [ ] 小節の先頭が `|` で分かる。
- [ ] 拍の区切りが `:` で分かる。
- [ ] ハイハット、スネア、バスドラの基本パターンが追える。
- [ ] 空白セルや休符相当の見え方が邪魔になりすぎない。
- [ ] アクセントやゴースト相当の記号が読み取りを妨げない。
- [ ] 凡例で `x` / `o` / `s` / `b` / `───` / 大文字 / 括弧 / `+` の意味を確認できる。

## Grid 解像度別確認

- [ ] 8th: `Count` が `1 + 2 + 3 + 4 +` の粒度で表示され、小節線・拍線・再生ヘッドが揃う。
- [ ] 16th: `Count` が `1 e + a` の粒度で表示され、サンプルのハイハット刻みが追える。
- [ ] 32nd: `Count` が `1 · e · + · a ·` の粒度で表示され、セル数が増えてもレーン位置が崩れない。
- [ ] 解像度を切り替えてから Play しても、`▶` が現在の Grid 解像度に沿って進む。

## Grid 表示設計メモ

- [ ] `docs/grid-notation-design.md` の現在の制約と次に直すべき点が、実装状況と大きくずれていない。

## サンプル JSON 確認

- [ ] `basic-rock-16th.json`: 4小節の小節ブロック、HH/SN/BD、クラッシュ、タム絡みを確認できる。
- [ ] `eighth-note-groove.json`: 8th 表示で8分グルーヴが読みやすい。
- [ ] `rock-fill-2bar.json`: 2小節目のタム回しとクラッシュ戻りが各レーンで追える。
- [ ] `thirty-second-check.json`: 32nd 表示で細かい HH/SN/BD が崩れず表示される。
- [ ] `long-rock-8bar.json`: 8小節が `=== Bars 1-4 / 8 ===` と `=== Bars 5-8 / 8 ===` に分かれ、各ブロックでレーン名が再掲される。

## Grid 自動確認

- [ ] `npm run check:grid` で全サンプル x 8th / 16th / 32nd の確認結果が表示される。
- [ ] 32nd 表示などで行長 warning が出る場合、warning と失敗を区別して確認する。
- [ ] `long-rock-8bar.json` の 16th 表示で2ブロックに分かれることを確認する。
