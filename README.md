# DrumTab Web

DrumTab Web は、読み込んだ MIDI / JSON / 音声・動画解析結果を、ブラウザ上で見やすいドラム譜・ドラムタブ譜に整えることを目指す Vite + TypeScript アプリです。

> 重要: 高精度な「音声からドラム音だけを分離・抽出する AI」は、このリポジトリの主戦場ではありません。外部サイト、DAW、別ツール、または将来の別モジュールで得た解析結果を取り込み、譜面として読みやすく整える体験を優先します。

## 現在できること

- MIDI / JSON / Audio / Video ファイルの読み込み
  - MIDI: `.mid`, `.midi`
  - JSON: `DrumTrack` 形式のイベント列
  - Audio: `.wav`, `.mp3`, `.ogg`, `audio/*`
  - Video: `.mp4`, `.webm`, `video/*`（音声を抽出して解析）
- ドラムイベントの簡易解析・表示
  - キック、スネア、ハイハット、シンバル、タム系のイベントを扱います。
  - 音声解析は簡易的なオンセット検出・分類を前提とします。
- Grid 表示
  - ドラムタブ風に各パートを横方向の時間グリッドへ並べます。
  - 強弱はアクセントやゴースト相当の記号へ変換します。
- Score 表示
  - VexFlow を使った簡易的なパーカッション譜表示です。
  - 現段階では「壊れにくい確認表示」を優先し、本格的な五線譜組版は未完成です。
- 再生
  - 読み込んだイベントを簡易ドラム音源で再生できます。
  - 再生速度を変更できます。
- MIDI 書き出し
  - 現在のドラムトラックを MIDI としてエクスポートできます。
- 量子化
  - 8分 / 16分 / 32分グリッドを選択し、量子化強度を調整できます。

## 現在の制約

- 音声解析の精度は限定的です。
  - 楽曲からドラムだけを高精度に分離する用途には向いていません。
  - 実用的な譜面化には、外部ツールで作った MIDI / JSON / ドラムステム解析結果の利用を推奨します。
- Grid 表示はまだ簡易テキストベースです。
  - 小節番号、拍、区切り線、休符・空白、ハイハット / スネア / バスドラの読みやすさは改善余地があります。
- Score 表示は試験的です。
  - リズムの統合、休符、タイ、連桁、複数声部、正確な符尾処理は未対応または不十分です。
- 編集機能は未実装です。
  - イベント追加、削除、ドラッグ移動、ベロシティ編集、コピー & ペーストなどは今後の設計対象です。
- サーバー機能はありません。
  - ログイン、サーバー保存、課金、外部 API 連携は行いません。

## 入力 JSON 形式

JSON は次の `DrumTrack` 形式を想定しています。

```json
{
  "bpm": 120,
  "events": [
    { "timeSec": 0.0, "durationSec": 0.08, "velocity": 0.9, "drum": "kick" },
    { "timeSec": 0.5, "durationSec": 0.08, "velocity": 0.8, "drum": "snare" },
    { "timeSec": 0.25, "durationSec": 0.05, "velocity": 0.55, "drum": "hh_closed" }
  ]
}
```

`drum` は以下をサポートします。

- `kick`
- `snare`
- `hh_closed`
- `hh_open`
- `crash`
- `ride`
- `tom_low`
- `tom_mid`
- `tom_high`

サンプルは `public/samples/` を参照してください。現在は以下を用意しています。

- [`basic-rock-16th.json`](public/samples/basic-rock-16th.json): 4小節の基本16分ロック。小節ブロック、同時打音、タム絡みを確認します。
- [`eighth-note-groove.json`](public/samples/eighth-note-groove.json): 8分主体のグルーヴ。8th 表示の読みやすさを確認します。
- [`rock-fill-2bar.json`](public/samples/rock-fill-2bar.json): 2小節目にタム回しとクラッシュ戻りを含むフィル確認用です。
- [`thirty-second-check.json`](public/samples/thirty-second-check.json): 32分の細かいイベントで 32nd 表示の崩れにくさを確認します。
- [`long-rock-8bar.json`](public/samples/long-rock-8bar.json): 8小節の基本ロック。4小節ブロック分割、レーン名再掲、後半フィルを確認します。

## 手動確認

主な手動確認項目は [`docs/manual-test-checklist.md`](docs/manual-test-checklist.md) にまとめています。特に既存の読み込み、表示、再生、MIDI 書き出しを壊さないことを重視してください。 Grid 表示の記号と設計方針は [`docs/grid-notation-design.md`](docs/grid-notation-design.md) にまとめています。

## 譜面化強化ロードマップ

### Phase 1: 壊れにくいドラムタブ表示

- Grid 表示をドラム譜・ドラムタブとして読みやすくする。
- 小節番号、拍、区切り線を明確にする。
- 8分 / 16分 / 32分表示切替でセル幅、拍線、再生ヘッドが破綻しないようにする。
- 空白セルと休符相当の見た目を整理する。
- ハイハット、スネア、バスドラの基本パターンを最優先で読みやすくする。

### Phase 2: JSON / MIDI 入力を譜面向けに正規化

- 入力イベントを小節・拍・サブディビジョンへ安定して割り当てる。
- 同一ステップ上の複数ドラムを正しく重ねて表示する。
- ベロシティをアクセント、ゴーストノート、通常音へ変換するルールを明文化する。
- MIDI ノート番号と `DrumName` の対応表を拡張・テストする。

### Phase 3: Score 表示を安全に改善

- 本格的な五線譜化より先に、例外で壊れない描画を優先する。
- 1小節単位での描画、休符の挿入、イベント数が多い場合の分割表示を追加する。
- キック / スネア / ハイハットの基本パターンが読み取れる範囲でパーカッション譜を整える。

### Phase 4: 手動編集の設計

- イベント選択、追加、削除、移動、ベロシティ変更を最小単位として設計する。
- 編集後の状態を JSON / MIDI 書き出しへ反映する。
- Undo / Redo、スナップ、複数選択、範囲コピーは後続段階で検討する。

### Phase 5: 外部ツール連携を前提にした取り込み品質

- 外部のドラム分離・採譜ツールが出力した JSON / MIDI を読みやすく変換する。
- このアプリ内では大規模な音声認識モデルや高精度なドラム分離 AI は実装しない。
- 入力フォーマットのバリデーションとエラーメッセージを改善する。

## このプロジェクトでやらないこと

- ログイン
- サーバー保存
- 課金
- 外部 API 連携
- 高精度なドラム分離 AI
- 大規模な音声認識モデル
- 最初から完璧な五線譜化
- UI 全面作り直し
